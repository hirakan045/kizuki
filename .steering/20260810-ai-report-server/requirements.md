# 要求内容 — AIレポート生成サーバー（WBS 5.1）

## 背景

AIレポート機能（F-3）はLLM呼び出しが必要だが、NFR-1-1「APIキーをアプリに埋め込まない。LLM呼び出しはサーバー側で行う」により、アプリから直接LLM APIを呼べない。サーバー側のプロキシを構築する。

## 対応要件

- PRD NFR-1-1: APIキーの秘匿
- PRD NFR-1-3: AIに送信するデータの範囲をプライバシーポリシーに明示する（このタスクでは範囲を固定するところまで。文言化は別途）
- WBS 5.1.1〜5.1.3

## 決定事項（このセッションで確認済み）

| 項目 | 決定 |
| ---- | ---- |
| LLMプロバイダ | Anthropic Claude API |
| モデル | `claude-sonnet-5`（禁止表現の遵守精度を優先。コスト差は日1回生成では無視できる） |
| デプロイ先 | Vercel |
| リポジトリ配置 | このリポジトリ内。`api/`をサーバーのルートにする（Vercelのゼロコンフィグ規約） |
| 呼び出し方法 | `@anthropic-ai/sdk`（生fetchではない） |

⚠️ **CLAUDE.mdの「本リポジトリはiOSアプリ専用」という記述と矛盾する。**理由：1人開発でリポジトリ管理を一元化したい、というユーザーの判断。CLAUDE.mdの更新は別途検討（このタスクでは行わない）。

## サーバーの責務（今回のスコープ = 5.1のみ）

- アプリから送られた「歩数・睡眠・幸福度・発見の素材」を受け取り、Claude APIでレポート文を生成して返す
- プロンプトの禁止表現制約（F-3のプロンプト制約）はサーバー側のシステムプロンプトに持つ
- 発見ロジック（5.2）・生成トリガー（5.3）は対象外。今回はAPIエンドポイントとして疎通するところまで

## 受け入れ条件

- `POST /api/report` に歩数・睡眠・幸福度・発見の素材を送るとレポート文が返る
- APIキーはVercelの環境変数にのみ存在し、リポジトリにコミットされない
- レスポンスの文言に禁止表現（勧誘・義務・目標提示・評価・未達の指摘）が含まれない
- ローカルでVercel CLIを使って動作確認できる

## 制約事項

- 想定リクエスト数は少ない（1人あたり1日1回）。認証・レート制限は最小限で良いが、無制限公開エンドポイントにはしない
- サーバーのコードはこのリポジトリのExpoアプリのpackage.jsonに依存を追加する形になる（依存混在は許容する、と決定済み）
